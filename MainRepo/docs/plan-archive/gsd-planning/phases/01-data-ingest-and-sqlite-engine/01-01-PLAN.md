# Plan 01-01: SQLite Schema, Fast DBF Streaming Reader, and Salted Premise Hasher

## Objective
Establish the database architecture (`outage_concierge.db`), build a high-performance Python streaming DBF reader that requires zero heavy geospatial dependencies, and implement the salted SHA-256 premise anonymizer.

## Context
- `Customer_Clip.dbf` is 78.8 MB with 117,642 records.
- We must avoid reading entire large DBF files into memory at once; a record-by-record binary streaming parser will convert raw bytes into SQLite batches in seconds.
- Premise hashing must use a persistent salt to produce deterministic anonymous IDs (`premise_key`) while never storing or exposing raw `premise_nu` or street addresses in application tables.

## Tasks
1. **Create SQLite Schema Migration (`ingest/schema.sql`)**:
   - `circuits`: `circuit_id` (PK), `substation`, `customer_count`, `premise_count`, `historical_damage_count`, `upstream_breaker`.
   - `premises`: `premise_key` (PK, hashed), `circuit_id`, `transformer_id`, `is_critical_tier`, `lat`, `lon`.
   - `damage_events`: `outage_num` (PK), `event_name`, `circuit_id`, `asset_type`, `report_time`, `repaired_time`, `status`, `access_issue`, `special_equipment`, `lat`, `lon`, `nearest_dist`.
   - `topology_edges`: `id` (PK auto), `premise_key`, `step_order`, `device_type`, `device_id`, `device_label`, `circuit_id`.
   - `labor_codes`: `cu_category` (PK), `description`, `avg_install_hours`, `avg_remove_hours`.
   - `labor_adders`: `adder_name` (PK), `description`, `adder_hours`.
   - `priority_facilities`: `facility_id` (PK), `facility_type`, `name_masked`, `lat_approx`, `lon_approx`.
2. **Implement Binary DBF Streaming Parser (`ingest/dbf_reader.py`)**:
   - Read 32-byte DBF header, field descriptors, and stream records directly from zip files without requiring full disk extraction.
   - Support types: `C` (Char), `N` (Numeric), `F` (Float), `D` (Date).
3. **Implement Premise Hasher & Key Generator (`ingest/hasher.py`)**:
   - Salted SHA-256 hash returning a clean 16-character hexadecimal key (e.g., `p_a1b2c3d4e5f60718`).
   - Store salt in local `.salt` file (gitignored).

## Verification
- Test script reads the first 10,000 records of `Customer_Clip.dbf` in <1 second.
- Verify hashing produces reproducible keys for the same `premise_nu`.
- Verify database tables are initialized with proper indices on `circuit_id`, `premise_key`, and `report_time`.
